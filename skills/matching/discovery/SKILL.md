# Job Discovery

Read [the Matching entry point](../SKILL.md) for shared boundaries and the selected-workspace website step. Follow [job discovery](../../../docs/job-discovery.md) for supported sources and screening ownership. Use this stage to gather verified observations; [matching and feedback](../feedback/SKILL.md) owns detailed assessment, ranking and round publication.

## Inputs and bounded research

Read fresh `matching context`, the selected candidate/profile and complete preferences, resume manifest, existing job library and source-specific discovery checkpoints. An empty resume manifest permits discovery, not application execution. Validate the library before writes. Candidate locations, qualifications, timing, category scope, exceptions and company limits come from those inputs, not this skill.

Use only SimplifyJobs/New-Grad-Positions for new leads under the current [discovery boundary](../../../docs/job-discovery.md). Inspect the Product Management section for PM and the appropriate section of that same repository for other confirmed directions. An empty categories filter records explicitly flexible directions: inspect relevant sections within this same repository and use actual responsibilities/background to identify leads, without asking for a target-title list. An empty locations filter does not supply relocation consent or work authorization. Do not use open web search, other lists or independent company-career discovery. Follow listed direct official links using Codex's in-app Browser and retain `simplify-new-grad` provenance. Verify New Grad eligibility and the actual graduation/start window; list membership is not proof. If the source has no suitable section or insufficient qualifying roles, show the limitation on the website and stop within scope. Do not install Simplify extensions or use autofill. Keep the local results tab available while verification runs in background tabs. Respect candidate batch/company limits and distinguish a bounded sample from a complete scan.

For incremental work, read each source's own completed checkpoint. If a complete delta is unavailable, inspect a deduplicated current listing and state the reduced precision. Advance a checkpoint only after the full scan and every inspected disposition are complete, including downstream assessment/publication where needed. An unfinished handoff leaves the prior checkpoint intact.

Website daily/catch-up requests use the same scope and checkpoint rules as manual discovery. Claim the exact saved request once; do not start another round while one is active. Complete it only after actual assessment/publication or a verified zero-change round, and attach the short actual completion receipt required by [daily updates](../../../docs/job-refresh.md). Incomplete or inaccessible work is blocked, not a successful timestamp. Routine unchanged automatic results stay on the website without extra chat status messages.

## Observe each official role

Verify requisition identity, employer, title, actual permitted work locations, employment type, responsibilities, required versus preferred qualifications, cohort/start timing, authorization restrictions and application limits. Capture short evidence references and actual observation dates. A generic careers-page redirect does not establish an open role. Avoid counting overlapping part-time research as additional full-time employment.

Record unknown employer conditions as research questions. Ordinary source uncertainty is research work; ask the candidate only for genuinely missing personal facts. Deduplicate by official requisition identity or canonical URL, removing only known tracking parameters. Reuse stable job IDs, merge real source attribution and preserve earliest first-seen dates.

Distinguish employer closure, user exclusion, expired event/referral links and connection failures. A failed connection or expired event link alone cannot establish employer closure. A different requisition is a different record. Do not reopen a protected record through Matching round publication; use the existing job interfaces with actual official evidence when an allowed availability update is needed.

## Handoff and permitted persistence

Hand off role observations, source references, verification times, qualifications, scope uncertainties and deduplicated IDs to [matching and feedback](../feedback/SKILL.md). Include operational failures and whether the source scan remains incomplete. Working observations may be held in a private temporary input; they are not another authoritative job list.

The common path publishes assessed roles through `matching publish`. When a narrow job-library update is needed, use the existing jobs CLI/domain APIs, validate afterward, and preserve Submission-owned lifecycle/identity. Matching may write `new` or `ready` only; a `ready` recommendation requires assessment, not merely finding a URL. Never fabricate `in_progress`, `final_review`, submitted evidence or verification dates.

Do not register employer accounts, upload resumes or submit applications. Report source-backed additions, material availability changes and operational failures. Rejected routine leads and internal screening notes do not create extra approval chores.
