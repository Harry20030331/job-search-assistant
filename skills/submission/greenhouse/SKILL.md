# Applying Through Greenhouse

Read `../SKILL.md` and `../../../docs/workflow-contract.md` before operating this ATS. They own canonical inputs, explicit category/CV routing, approved answers, review, submission and recovery. This module adds platform-specific techniques.

## Greenhouse Technique

Greenhouse often renders unopened dropdowns as `Select...`. Treat that as unanswered, even when nearby text looks populated. Observe the full field label, open the visible control, choose only a locally supported answer, and confirm the displayed selection.

Resume parsing, uploads, validation, or dynamic questions can rerender the same page. Re-observe after every such event; never continue from remembered state. For repeated Yes/No or demographic controls, bind the choice to the complete visible question and section rather than shared answer text or position.

Greenhouse may place the final `Submit application` button on the same page as ordinary fields, with no separate review screen. Before any bottom-of-page action, read its exact visible label. Use ordinary progression only when it is clearly not final submission.

## Answer Policy

Never guess unknown sensitive, legal, identity, security, personal-history, credential, or exercise facts. Add them to the review list. Accept required terms and authorized required processing consent; reject optional marketing, talent-community, SMS, affiliate, promotional, or unrelated sharing consent.

## Completion Check

Review every formerly `Select...` field, uploaded filename, repeated radio group, consent, validation message, and generated answer. Stop before `Submit application` or any equivalent final action. Report the explicit category, PDF filename, unresolved questions, and review items.

## Scenario Self-Check

If an upload fills parsed fields, several dropdowns still show `Select...`, and a submit button appears below them, the correct response is to re-observe, complete only supported fields, verify the file, and stop before that button.


Final submission permission and authorization sources are defined only by the common workflow contract. These checks do not require a second approval after exact user acceptance.
