# Applying Through Lever

Read `../SKILL.md` and `../../../docs/workflow-contract.md` before operating this ATS. They own canonical inputs, explicit category/CV routing, approved answers, review, submission and recovery. This module adds platform-specific techniques.

## Lever Technique

Lever commonly presents many radio groups whose choices repeat labels such as Yes, No, or Decline. Identify each group from the full visible question and surrounding section before choosing. Never use shared answer text, visual order, or a remembered position to target a radio.

Lever custom questions can surface personal-history matters such as prior applications, prior employment, relatives, non-competes, disciplinary history, or other company-specific facts. Use a local default only when `preferences.md` explicitly covers the exact meaning. A similar-looking question is not equivalent. Unknown sensitive, legal, identity, security, personal-history, credential, or exercise facts go to review and are never guessed.

Uploads, validation, conditional follow-ups, and navigation can alter the visible groups. Always re-observe after each event and confirm that each selected answer remains attached to its intended full question.

## Consent Policy

Accept required terms, truthful certifications, and authorized required processing consent. Reject optional marketing, talent-community, SMS, affiliate, promotional, and unrelated data-sharing consent. Distinguish each checkbox by its complete wording.

## Stop Boundary

Review the mapped PDF filename, every radio group, personal-history answer, consent, validation message, and generated response. Proceed through nonfinal `Next` or `Review` only after verification. Stop before `Submit application` or any equivalent final action and report all unresolved or human-review items.

## Scenario Self-Check

If three Yes/No groups ask about work authorization, prior employment, and relatives, answer each only from its complete prompt and local source; do not let one repeated `No` control stand in for another.


Final submission permission and authorization sources are defined only by the common workflow contract. These checks do not require a second approval after exact user acceptance.
