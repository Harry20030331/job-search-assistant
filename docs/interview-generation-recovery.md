# Interrupted practice generation verification

Maintenance date: 2026-10-31. This repair covers website practice attempts; it does not add inbox monitoring or change application/calendar approval, the shared opportunity schema, model prompts, historical evaluation results or the frozen UI v5 files.

## Behavior

Running workers renew a 120-second lease every 15 seconds. Dashboard exports expose expired queued/running attempts as `failed` with `generation_interrupted` without mutating storage. The existing Plan-tab Retry control explicitly retires that attempt and creates a new one after checking the exact current plan and sources. Nothing restarts automatically. Attempts and their diagnostic pointers remain available, and the current plan's original approval is retained.

The host binds generation to its job ID and workspace. It rechecks the lease immediately before model invocation and inside the material transaction. A late worker cannot publish after expiration or after another retry; ready status commits with the pack. Failure to write subsequent diagnostics cannot turn a saved pack back into a failed attempt. A failed duplicate process launch cannot cancel another active worker.

The next website write adds a nullable `heartbeat_at` column under the existing SQLite transaction lock, preserving historical rows. Reads support both schemas without migrating data. Lease renewal changes only that private heartbeat, keeping the public status timestamp stable so page polling does not repeatedly reload. Historical non-heartbeating rows expire by their existing timestamps. Upgrade with old workers stopped: a process that loaded an older implementation cannot acquire the new publication fencing retroactively. Local clock jumps and suspended workers can expire an attempt; the user must explicitly retry. An orphaned model subprocess might consume quota after a host crash; this repair prevents stale publication rather than guaranteeing cancellation of that subprocess.
