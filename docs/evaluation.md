# Submission 评测框架

2026-10-15 确定，后续在此迭代。本文是方案，尚非正式评测结果；当前先整理已有案例、准备 Demo，暂不启动完整测试。

## 测试矩阵

**5 个 candidate × 10 个岗位＝50 次运行；覆盖 5 个 ATS 平台，每个平台选 2 个不同岗位表单。**

- 跨平台：检验平台适应能力。
- 跨 candidate：检验信息复用、填写与判断能力。
- 同平台不同岗位：检验公司自定义题目的差异。

五个 candidate 在经历、工作许可、偏好和选填信息完整度上有所不同，具体人设与岗位待选。可分两轮各 25 次；若第一轮用于调试，第二轮作为保留测试，结果分开报告。

## 候选人资料

所有测试 candidate 均须补齐必填项，才开始自动填写；选填项为空不阻拦。

- **必填：**身份与联系方式、教育及适用 GPA、工作经历、核心技能、求职方向、入职时间、remote／hybrid／on-site 与地点／搬迁偏好、工作许可及移民支持需求、简历。
- **必填身份选择：**国籍、永久居民、庇护／难民身份及相关身份变更历史；自愿身份披露须选择具体回答或“不愿披露”。无或不适用可以明确记录。
- **选填：**亲友任职表、个人链接、薪资期望、教育／项目补充、面试时间偏好。亲友表为空不自动等于 No，须有用户明确的默认设置。
- **不纳入标准资料：**一般服役经历、合同限制；遇到时在具体申请中询问。一般服役经历与 protected veteran 披露分开处理。

未填的选填信息若被岗位要求，或岗位条件超出既有偏好，则进入 Review。完整必填校验尚待实现。

## 标准答案与指标

运行前逐题标注：**应自动填写／应进入 Review／可留空**，并写好可接受答案或判断标准。根据实际表单与 Review 评分，开放题看事实依据与相关性。

| 指标 | 计算方式 |
| --- | --- |
| 自动填写 Precision | 正确自动填写数 ÷ 实际自动填写数 |
| 自动填写 Recall | 正确自动填写数 ÷ 应自动填写数 |
| Review Precision | 正确提出的问题数 ÷ 实际提出的问题数 |
| Review Recall | 正确提出的问题数 ÷ 应提出的问题数 |

正确自动填写要求“本应自动填，且答案正确”；猜中需要用户判断的答案也不算正确。重复提问不重复计功，分母为零记 N/A。

另记录 **时间**（读取材料至 Review 就绪并停止，人工等待另记）与 **Token**（实际输入／输出用量，无法取得则标缺失）。失败运行也保留成本。

## 运行与结果

每次使用独立状态，停在真实提交之前；Approve 仅代表内容已审阅。固定输入、评分标准、模型、工具与预算，保留首次结果，修复重跑另记。

每次一行记录：candidate、平台、岗位、版本、完成／阻塞状态、四项指标及原始计数、时间、Token、证据。按平台与 candidate 汇总，不混合不同版本结果。

**未经授权提交、混用候选人信息、编造关键事实**单独登记为严重错误，不被平均分抵消。登录／验证／页面失效等阻塞另记。
