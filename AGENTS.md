# Contributor and Agent Guide

- Read the root README and the relevant module README before making changes.
- Keep documentation and code in English; keep instructions concise.
- Each module owner maintains its workflow, setup, test cases, metrics, and evaluation runner.
- Work in a feature branch and use a pull request for team review.
- Keep module changes independent. Agree on shared interfaces before changing cross-module behavior.
- Build on the Codex harness; make domain logic, tools, and state explicit.
- Never invent applicant facts. Ask the user when information is missing or ambiguous.
- Obtain user authorization before submitting applications, sending messages, or changing calendar events.
- Keep personal data and credentials outside the repository. Use fictional fixtures; inspect staged changes before committing.
- Evaluate against basic instructions under comparable Codex conditions. Separate development and held-out cases; record failures, corrective user effort, and cost.
- Run relevant checks and report what was tested. Do not claim unfinished workflows or unmeasured improvements work.
